# Marginalia for Android

Copy Marginalia.apk to an Android 8 or newer device and tap it in Files to install. If Android prompts, allow that file manager to install this APK. The app runs offline. Signing in to sync is optional.

### Move a library

Import reads older and hand-edited backups leniently: missing dates, odd ratings and stray fields are repaired, and a record that cannot be read is left out and listed in the import preview instead of rejecting the whole file. A file that isn't a Marginalia backup, or was made by a newer version, says so.

For a new library, start with the [editable JSON template](examples/marginalia-template.json).

In your original HTML tracker, open Settings and export its JSON backup. In the Android app, open **Settings & files → Import and merge**. Select individual records or the whole backup, review the counts and tap **Apply merge**. Cancel leaves the library as it was.

The app saves edits on the device. **Link a new file** creates a portable JSON copy and updates it after each save. Use **Export backup** for a separate snapshot or **Share backup** to send it to another device. If another app edits the linked copy, Marginalia keeps your device copy and shows a warning. Import the changed file to reconcile it, then link a fresh file.

Different record IDs survive a merge. For edits to the same record, the newer timestamp wins. A deletion wins when equally recent or newer. These rules apply to whole records, including their notes. Independent entries with the same title stay separate. Export before uninstalling to keep a portable backup.

### Filter the library

Open **Library → Sort and filter**. Include or exclude values in each section. **Match all** requires every included genre or year within that section. **Match any** accepts one. Exclusions always win. Tap an active filter to remove it, or use **Clear all**.

### Accounts and sync

Sync is optional. Without signing in, the library stays on the device as before. In **Settings & files → Account & sync**, create an account (the server owner gives you an invite code) or sign in. The library is saved on the device first, then merged with the account using the same rules as **Import and merge**, so edits made offline are kept. Sign in on another device, or the desktop page, and they stay in step. In the browser and the desktop app, **each account keeps its own library on the device** (plus a Guest library for anything not in an account). **Add another account…** signs a second account in without signing the first out, and **Accounts on this device** switches between them instantly: nothing is replaced, copied between accounts or mixed. Signing out keeps that account's library and any edits you make afterwards, and they merge into the account when you sign in again. A library that is not in any account (Guest) is offered to a brand-new account you sign in to, never to an existing one, and you can decline to keep it separate. Only the account you are viewing syncs, and a sync in flight is dropped if you switch. **Remove from this device** deletes an account's local copy and sign-in; its library stays on the server. An existing library is moved into its account's slot the first time this version loads, with a backup kept under `marginalia.data.v1.premigration`. The Android app still keeps a single library per device: signing in as a different account there replaces it after a confirmation.

`server/` is a small Node server that serves the page and stores one library per account in Postgres. Set `DATABASE_URL` and `INVITE_CODE` (registration is closed when it's unset) and run `node server/index.js`. The `Dockerfile` builds it. The Android app now has the Internet permission and reaches only the hosted address, enforced by the page's Content-Security-Policy. To use your own server, change the address in `index.html` (`API_BASE` and the CSP `connect-src`) and in the unit-test hash policy by editing the script as usual.

To reset a password, run `npm ci` in `server/`, then `DATABASE_URL=<database URL> node reset-password.js <username>`. Use the Postgres service's public URL from your own computer. It sets a random temporary password (printed once) and flags the account. At the next sign-in the user is asked to choose a new password, and nothing else works until they do. Add `--flag-only` to force a change without touching the current password, or set `TEMP_PASSWORD` to pick the temporary one. Either way the account is signed out everywhere and its library is untouched.

### Feature flags (per-user rollout)

Features can be switched on or off per account, so new functionality can reach chosen users first. A flag resolves in this order: the account's own setting, then the database default, then the default in the code. Everything that exists today defaults to on, so an account with no setting keeps it all. Signed-out use always follows the defaults in the page.

Current flags: `franchises`, `stats`, `wrapped`, `file_link`, `shortcuts`, `drag_drop_import` (all on by default) and `version_history`, `offline_app`, `quick_add`, `sync_notices`, `covers`, `cover_fetch`, `ao3_fetch`, `tags`, `progress`, `lists`, `stats_plus`, `import_trackers`, `sharing`, `library_actions`, `next_up`, `genre_manager`, `saved_views`, `listening_stats`, `duplicates`, `export_all`, `undo`, `editions` (off by default, so they reach only the accounts you switch them on for). Manage them with `server/flags.js` (same `DATABASE_URL` as the password script):

```
node flags.js list                       # every flag, its defaults and per-user settings
node flags.js show alice                 # what alice actually gets
node flags.js off stats alice            # turn a flag off for one account
node flags.js on new_editor alice        # turn a flag on for one account
node flags.js clear new_editor alice     # back to the default
node flags.js default on new_editor      # roll out to everyone without a setting
```

To ship something new to chosen users: add the flag in `index.html` (`FEATURES`, as `false`), wrap the feature in `feat('new_editor')`, deploy, then `node flags.js on new_editor <user>`. Accounts pick up changes at their next sync, within about a minute or when they reopen the app. Flags hide features in the page. They don't enforce anything on the server, which can check a flag with `featureOn()` in `server/features.js` when needed. By hand in SQL: `INSERT INTO user_features(user_id,flag,enabled) SELECT id,'new_editor',true FROM users WHERE username='alice' ON CONFLICT (user_id,flag) DO UPDATE SET enabled=true;`

### Admin, history, offline app, quick add and sync notices

- **Admin page** (`#/admin`, only for accounts marked admin; enforced on the server). Create the first admin by setting the `ADMIN_USERS` variable on the server to a username (comma-separate several), or with `node admin.js grant <user>`. Admins can reset a password (a temporary one is shown once and the user must change it at next sign-in), require a password change, sign someone out everywhere, make or remove admins, delete an account, turn feature flags on or off per account or for everyone, and rotate or close the invite code. Admins see counts and sizes, never anyone's entries.
- **Version history** (flag `version_history`). The server keeps up to 40 snapshots per account: at most one every 15 minutes while you edit, always before a change that removes entries, and always before a restore. **Settings → Version history → Restore** brings an earlier snapshot back on every signed-in device (restored records get fresh timestamps so the merge accepts them), and today's library stays as a version, so a restore can be undone.
- **Installable offline app** (flag `offline_app`). Adds a web manifest and a service worker so Chrome, Edge and phones can install the site and open it offline. The page comes from the network when it can and from the cache when it can't. Sync calls are never cached. Turning the flag off removes both.
- **Quick add** (flag `quick_add`). One line on Home, for example `Dune by Frank Herbert, book, finished, 4 stars, #scifi, in Dune saga, 2026-03-12`. Details after the title are matched by what they look like: a type (book, film, tv, game, play, escape, online), a status (planned, reading, finished…), a rating (`4 stars`, `4.5/5`, `4*`), `#genres`, `in Franchise`, `by Creator`, and `today`, `yesterday` or a date. Anything else becomes a note. `q` jumps to it.
- **Sync notices** (flag `sync_notices`). When a sync brings in changes it says what changed, and when the same record was edited on two devices it says which version won (the newer edit). **Settings → Recent sync activity** keeps the last 25.

### More features (all behind flags)

- **Covers and links** (`covers`). Add a cover image and a web link to any entry in the editor. Covers are shrunk in the browser to about 10 KB and stored in the library, so about 600 fit before the library nears its 10 MB limit (the editor refuses past 8 MB). Links must be `http` or `https`; anything else is discarded. In the Android app a link opens in the system browser.
- **Tags separate from genres** (`tags`). Every entry has two label lists. **Genres** are broad categories (fantasy, sci-fi); **tags** are free labels such as tropes, pairings and moods. With the flag on, the editor has a *Tags* field, cards and pages show tag chips (dotted outline, next to the dashed genre chips), the Library gets a *Tag* filter, search and `entries.csv` (a *Tags* column) include them, Stats shows *Top tags*, and the select-many bar gets *＋ Tag / − Tag*. Quick add keeps `#genre` and adds `tag: slow burn` (repeat it for several). Goodreads shelves, StoryGraph tags and Letterboxd tags import as tags, and AO3 fetches put their tags there too (fandom still becomes the franchise). **Settings → Tags** lists every tag with counts and can rename or merge, remove, or turn a tag into a genre; the genre manager has the reverse (*Make it a tag*), and one button moves the genres of all fanfiction entries to tags (undoable). With the flag off nothing changes and labels stay in genres. The data keeps a separate `tags` list on each entry; older apps simply ignore it.
- **Find missing covers automatically** (`cover_fetch`, **Settings → Find missing covers automatically**, a device setting, off by default). While the page is open and you are signed in it looks up covers for books that have none, one every 7 seconds, using the same server lookup as *Find covers*. It never shows a notice or toast: progress, pauses and problems appear only in the status line in Settings. Placeholder titles (`AO3 #123`, `ISBN …`), non-books and entries that already have a cover are left alone; a book nothing matches is not tried again for a month; it backs off quietly on errors and stops (saying so in that line) if the library is near its size limit.
- **Fetch stories from AO3** (`ao3_fetch`, needs a signed-in account). Paste an AO3 work link into the editor's *Fetch from AO3* box (or into Quick add, e.g. `https://archiveofourown.org/works/123, finished, 4 stars`) and the server reads the work's public page (`GET /api/ao3?id=`, one request at a time, 300 an hour per account). You get the title, author, rating, word count, chapters, kudos, fandom, relationships, characters, tags and summary. Before anything is added a review screen lists every incoming tag: untick to drop it, pick one of your own tags to use instead (it suggests likely matches such as GoT → game of thrones), or ignore it, and tick *remember* so the choice applies automatically next time. Remembered choices live in the library (`tagRules`, merged across devices) and are listed under **Settings → Tag rules**. The first fandom becomes the franchise. **Fetch from AO3** in the select-many bar fills in selected stories that already have an AO3 link (100 at a time), replacing placeholder titles such as `AO3 #123` and using only tags you already know. Works that need an AO3 login can't be read, and AO3 may refuse automated requests from the server; the page says so when it happens.
- **Fanfiction type.** Fanfiction is its own entry type next to Book (site, word count, chapters, current chapter, and AO3 rating and kudos when `ao3_fetch` is on). Quick add understands `fanfic`/`fic`/`ao3` as the type. AO3 fetches and the media-app CSV import create Fanfiction entries; with `progress` on, an ongoing story gets a *+1 chapter* button. Re-importing the media-app CSV also retypes stories you already hold as books (the preview says how many) while keeping your ratings and notes. Books you already have that look like fanfiction (format "Fanfic", or an AO3 or fanfiction.net link) show a **Move to Fanfiction** button in Settings, undoable, and *Fetch from AO3* on such a book also converts it.
- **AO3 pacing and background fill-in.** AO3 throttles automated readers, so the server fetches one work at a time with a 5 second gap, remembers each work for an hour, and when AO3 answers 429 it waits the requested time once and retries, then shares a cool-down across everyone so it stops asking (the page is told how long to wait). **Settings → Fill in AO3 stories automatically** (device setting, off by default) works through stories that still have a placeholder title (`AO3 #123`), about one every 6 seconds, using only tags you already know. It runs only while the page is open and you are signed in, does nothing while you are editing, backs off when AO3 asks, and skips stories AO3 won't show (deleted or login-only) for a week. Its changes are not individually undoable; with version history on you can restore an earlier library.
- **Importing the "media app" CSV.** The tracker importer recognises that export (`source_uuid`, `run_finished_dates` columns): AO3 and fanfiction.net rows become Fanfiction entries (ISBN rows stay books), with their link, word count, ratings, read-through dates, franchises, shelves as lists and favourites as a *Favourites* list. Year-only and month-only dates are padded and annotated. Titles in that export are placeholders (`AO3 #123`), which *Fetch from AO3* can fill in. Big libraries draw the first 600 cards of the Library and add more on request.
- **Find covers automatically** (`cover_fetch`, needs `covers` and a signed-in account). The editor gets a *Find cover online* button, and the library's select-many bar gets *Find covers*, which looks up a cover for each selected book that has none (one undo reverts the batch). The page itself cannot reach image sites, so it asks the server (`GET /api/cover?title=&creator=&asin=`), which tries Audible's catalogue (when the entry came from an Audible import, using its ASIN), then Open Library, then Google Books, and returns the image; the page shrinks it like any uploaded cover. The server only contacts those fixed hosts, never a caller-supplied address, rejects files over 2 MB, and allows 600 lookups per account per hour. Books nothing matches are skipped and reported.
- **Progress buttons** (`progress`). On Home and on an entry: **+10 pages**, **+25 pages**, **Next episode** (`S2E5` becomes `S2E6`, `12/24` becomes `13/24`), **+1 h**, **+5 h**, **Start** and **Finish**. Finishing stamps today's date.
- **Lists** (`lists`). Named collections that cut across franchises ("to read this winter", "recommended by Sam"). Add entries from a list's page or an entry's page, filter the Library by list, and add `list: Name` to a quick-add line. Two devices that create a list with the same name offline are merged into one.
- **More stats** (`stats_plus`). Finished per year by type with the change on the year before, average stars by genre and by type, finished per month over the last year, and **Year wrapped → Save as image** (a PNG in the browser and desktop app; not in the Android app).
- **Import from other trackers** (`import_trackers`). Goodreads, StoryGraph, Letterboxd and Audible exports and any CSV with a Title column, through the same review screen as Import and merge. For Audible, export your library with [Libation](https://github.com/rmcrackan/Libation) as JSON or CSV. Each audiobook becomes a book with format Audiobook, its narrator and length (two extra book fields shown while this flag is on), a link to its Audible page, genres from its categories, the date added as its date added, a rating where you gave one, and finished or planned from Libation's finished flag (the export has no finish dates). Series become franchises when you own two or more books in them; the series and volume also go in the Series / volume field. Sleep and podcast episodes and returned, unfinished books are skipped. Imported records are stamped old on purpose, so importing the same file twice adds nothing, your own edits win, and anything you deleted stays deleted.
- **Share links** (`sharing`, enforced on the server). A read-only link to a franchise, a list or the whole library that anyone can open without an account. It shows your current library and stops working when you revoke it. Notes are shared only if you tick **include my notes**. Entry links, mixed ratings, franchise and list membership, and deleted records are never included. Manage links in **Settings → Share links**.

- **Library actions** (`library_actions`). Makes the Library page interactive. Each card has tappable stars (tap the same star again to clear), **Start** and **Finish** (or **Already finished**, which marks a book finished without inventing a date) and an **Add to list** menu. Tap a genre, franchise or status chip to filter to it, and tap again to clear; cards show three genres plus a **+N** button that opens the rest. Tick cards to select them and a sticky bar offers set status, add to list, add or remove a genre, and delete (it warns when selected books are hidden by a filter, and, with Version history on, that deleted books can be restored). Clicking a card opens a preview panel (a bottom sheet on phones) with its details and the same actions, so you keep your place; Esc closes it.

- **Next up in a series** (`next_up`). Franchises are ordered by the volume number in the Series / volume field (`#3`, `Book 3`, `Vol. 2`). Home shows the next unread book in every series you've started and aren't currently reading, with a Start button. A franchise page lists its books in volume order, marks the next one, and can build or refresh a "Series order" timeline. A book's page shows its place in the series with previous and next links. Series need at least two numbered books.
- **Listening stats** (`listening_stats`). For audiobooks with a length: hours listened and still to listen to, average length, hours by year (needs finish dates), by genre, narrator and author, audiobook length buckets, and an "hours listened" card in Year wrapped.
- **Tidy up** (`genre_manager`, `duplicates`). A page for cleaning the library after imports. *Genres*: rename, merge several into one (renaming to an existing name merges), delete, jump to the books that have one, and suggested merges for spellings that differ only by punctuation, plurals or `sci-fi` against `science fiction`. *Duplicates*: groups entries of the same type with the same title (ignoring case, punctuation, "The", "(Unabridged)" and subtitles such as "Kenobi: Star Wars Legends") and a matching author. Choose the one to keep, untick any entry that is really a different book, and the rest are merged into it: dates, rating, notes, genres, lists, links and timeline places are combined. "These are different" is remembered and synced.
- **Saved views** (`saved_views`). Name the current Library filters, switch between views from the bar above the library, update a view when you change its filters, and pin views to Home, where they show a live count. Views sync between devices.

- **Export everything** (`export_all`). **Settings → Export everything** downloads one zip: `marginalia-library.json` (restore it with Import and merge), `entries.csv` for spreadsheets (UTF-8 with a BOM so Excel reads it, and cells that look like formulas are neutralised), your cover images as files under `covers/`, `settings.json`, and, when signed in, `account.json` (username, creation date, switched-on features) and `shares.json` (your share links, whose tokens are secrets). A checkbox adds the server's version history under `versions/`. If the server can't be reached it still exports the local library and says what it left out. Not available in the Android app, which has its own Export backup.
- **Undo** (`undo`). With this on, deleting a book, a list, a view, a franchise, a timeline or a genre, merging duplicates or genres, bulk status, list and genre changes, building a "Series order" timeline and applying an import show an **Undo** button for ten seconds instead of asking first (**Ctrl/Cmd+Z** undoes the last of the last five actions in a session, except inside a text field). Undo reverts only the records the action changed, and leaves alone anything you edited since (it says how many). Restored records get fresh timestamps so synced devices accept them. Deleting 25 or more books at once still asks first. An undone import is recorded as deleted, so importing the same file again will not add those books back.

- **Editions** (`editions`). Link entries that are the same book read by different narrators (or any other repeat of the same book you want reviewed separately). Nothing is merged: every edition keeps its own rating, feeling, notes, dates and status, and has its own page. A linked group takes **one place** in the Library, Home, franchise and list pages and in series order and Next up: the card shows the edition that is furthest along (finished, then in progress, then the rest), with the others as chips (by narrator) that open that edition. An edition that is planned is not listed as "to do" when another reading is finished or in progress. Stats count books once, while ratings, feelings and the mixed rating count every edition because each is its own review. Link from a book's page (**Editions of this book**, likely matches first), from **Tidy up → Duplicates** (**Link as editions**), or by ticking books in the Library (**Link as editions**); linking groups that already have editions joins them whole, **Unlink** takes one out, and a group of one is dissolved. The group id (`workId`) is a normal field, so it syncs, restores from backups and appears in the spreadsheet export as **Edition group**. Bulk actions on a card apply to the edition it shows.

### Mixed rating

Besides stars and a feeling, every entry can carry a **mixed rating**: one answer to two questions at once, such as "was it fun?" and "was it good?". It started life as the "food scale" (steak, hamburger, cod liver oil, stale cracker) and is now a general feature. Under the hood each answer is one of four stored codes in the entry's `mix` field: `hh` (yes to both questions), `hl` (yes to the first only), `lh` (yes to the second only) and `ll` (no to both). A **scale** is just the names and icons for those four answers, so changing the scale in **Settings → Mixed rating** relabels everything (the editor, entry pages, the Library filter, Stats, Year wrapped and the spreadsheet export) and never changes or loses a rating.

Built-in scales: *Food scale* (the original, and the default), *Enjoyment and quality* (brilliant, guilty pleasure, worthy, a miss), *Effort and reward*, *Heart and head*, and *Light and deep*. **Custom** lets you name both questions and give all four answers an icon, a label and a hint. **Off** hides the mixed rating everywhere and keeps the ratings you have already given. The choice is a setting on the device (like theme and text size), and the ratings themselves sync with the library.

Libraries, backups, version-history snapshots and saved views written by older versions (with the old `food` field and `steak`/`burger`/`codliver`/`cracker` values) are converted automatically when they load, and a library is saved in the new form the first time it is converted. The Year wrapped cards for the best, worthy-but-hard and worst answers follow whichever scale is active. In the spreadsheet export the column is **Mixed rating**, holding the active scale's labels (or the raw code when the scale is Off).

### Desktop app (Windows, macOS, Linux)

`desktop/` is an Electron wrapper around the same page, so it works offline and signs in to the same account for sync. Links open in your browser, and the window only ever shows the app page. It keeps its library in the app's own storage, so it uses account sync and Export backup rather than the browser's linked file.

```
cd desktop
npm install
npm start          # run it
npm run dist       # build an installer for the current OS (dmg, nsis or AppImage/deb)
```

The **Desktop app** workflow builds all three on GitHub (run it from the Actions tab). Installers aren't code-signed, so Windows SmartScreen and macOS Gatekeeper will ask you to confirm the first launch.

### Use it on desktop

Hosted at https://web-production-ac96f798.up.railway.app (Railway, built from the `Dockerfile` in this repo). Your library stays in your own browser. Opening the address on a new device starts empty, so move data with export and import.

To run it locally instead:

The app is a single offline page, so it also runs in a desktop browser. Open `app/src/main/assets/index.html` in Chrome or Edge (or copy that one file anywhere and open it). Nothing is uploaded.

- **Same library as your phone:** use **Export backup** on one side and **Import and merge** on the other. You can also drop a backup `.json` file onto the page.
- **Linked file:** in **Settings & files**, **Link a file** saves a JSON copy after every edit, the same way the Android app does. The browser asks permission again after a restart, so use **Reconnect file**. If another app or device changes the linked file, Marginalia keeps your browser copy and warns you. Import the file, then link a fresh one. Browsers without this feature (Firefox, Safari) keep the library in the browser only, so export backups regularly.
- **Keyboard:** `/` search, `n` log something, `Ctrl`/`Cmd`+`S` or `Ctrl`/`Cmd`+`Enter` save the open entry, `Esc` close.
- Wide windows use extra columns, and the entry page shows details beside notes.

### Build from source

Open the extracted project in Android Studio with SDK Platform 35 installed. Build a debug APK or run `gradlew.bat :app:testDebugUnitTest :app:assembleDebug` on Windows. On macOS or Linux use `sh gradlew :app:testDebugUnitTest :app:assembleDebug`. The APK is written to `app/build/outputs/apk/debug/`. First-time builds download dependencies.
